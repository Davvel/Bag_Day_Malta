NOTICEBOARD LOCATIONS — FRONTEND v1.1.126 / BACKEND v1.1.35

INSTALL BACKEND FIRST
Extract the backend ZIP into a new folder. In PowerShell, run these three
commands from that extracted folder, one at a time. Continue only after success:

.\1_Check_and_Backup_API.ps1
.\2_Deploy_API.ps1
.\3_Verify_API.ps1

Step 1 checks the existing installation, recovers its configuration and backs up
its database. Step 2 applies the additive migration and deploys the API.
Step 3 verifies the deployed API. No separate SQL command is required.
The sponsor exporter is unchanged; step 4 is not needed for this release.

THEN INSTALL FRONTEND
Copy everything inside 2_WEBSITE/COPY_TO_GITHUB from the frontend ZIP into the
website repository, replacing matching files. Commit and publish through
GitHub Desktop as usual. Reload any open editor tabs after both deployments.

WHAT CHANGES
- Notice details have a source icon/name/date title bar, proper close button,
  white modal border, faded backdrop, and full wrapping 22px/26px titles.
- Public details omit categories/audiences and show locality plus Where.
- Categories/audiences use optional checkbox dropdowns, 0–5 per group, no chips.
- Untagged notices match All filters, not arbitrary specific tags.
- Where is required on create and on the next save of an existing notice.
- Existing notices remain readable and publishable without rewriting history.
- The precise map pin is optional. Open the map at the locality centre,
  zoom/pan/tap or drag the pin, then explicitly confirm it. Cancel discards changes.
- There is no automatic address search, geocoding service, API key, billing
  account or credit card. The map uses Leaflet with OpenStreetMap tiles.
- Starting coordinates are bundled for all 68 localities and seeded into the
  locality table. Database centres take priority; bundled centres are the
  fallback, then the centre of Malta. Centres are never automatically saved
  as event pins. Malta/Gozo Rabat and Zebbug are distinguished.
- Pins can be changed or removed. Only confirmed pins become public Maps links.
- Google Calendar receives Where plus the locality in its location field.
- A map failure is handled quietly: keep the Where field, leave the pin optional,
  and hide the unavailable picker for that form. Previously saved pins remain
  until explicitly changed or removed. The street map needs network access.
- All frontend v1.1.125 functionality and previous backend changes are retained.

DATABASE / PUBLICATION
New notice fields: where_text (300 characters), nullable latitude/longitude.
New locality fields: center_latitude, center_longitude, center_source.
Migration is additive and repeatable; it preserves existing rows and non-null
custom locality centres. New notice data is included in published snapshots,
static CSV and compatibility JSON. Locations stay private until Publish.
